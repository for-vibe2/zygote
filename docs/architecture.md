# Архитектура компилятора Zygote

## Обзор

Zygote следует классической многопроходной архитектуре компилятора с четкой фазовой структурой.

## Фазы компиляции

### 1. Лексический анализ (Lexer)

**Файл:** `src/lexer.s`

**Задачи:**
- Чтение символов из исходного файла
- Группировка символов в токены
- Распознавание ключевых слов, идентификаторов, чисел, операторов
- Пропуск пробелов и комментариев

**Токены:**
- `TOKEN_NUMBER` - числовые литералы
- `TOKEN_IDENTIFIER` - идентификаторы переменных/функций
- `TOKEN_KEYWORD` - ключевые слова (int, return, if, else, while)
- `TOKEN_OPERATOR` - операторы (+, -, *, /, =, ==, <, >)
- `TOKEN_DELIMITER` - разделители (;, {, }, (, ))
- `TOKEN_EOF` - конец файла

**Функции:**
```assembly
lexer_init:          # Инициализация лексера
get_next_token:      # Получить следующий токен
skip_whitespace:     # Пропустить пробелы
read_number:         # Прочитать число
read_identifier:     # Прочитать идентификатор
is_keyword:          # Проверить, является ли токен ключевым словом
```

### 2. Синтаксический анализ (Parser)

**Файл:** `src/parser.s`

**Задачи:**
- Проверка синтаксической корректности
- Построение абстрактного синтаксического дерева (AST)
- Обнаружение синтаксических ошибок

**Типы узлов AST:**
- `NODE_PROGRAM` - корень программы
- `NODE_FUNCTION` - определение функции
- `NODE_VARIABLE` - переменная
- `NODE_NUMBER` - числовой литерал
- `NODE_BINARY_OP` - бинарная операция
- `NODE_ASSIGNMENT` - присваивание
- `NODE_RETURN` - оператор return
- `NODE_IF` - условный оператор
- `NODE_WHILE` - цикл
- `NODE_BLOCK` - блок операторов

**Структура узла AST:**
```
[type:8] [value_ptr:8] [left:8] [right:8] [next:8]
```

**Функции:**
```assembly
parser_init:              # Инициализация парсера
parse_program:            # Парсинг всей программы
parse_function:           # Парсинг функции
parse_statement:          # Парсинг оператора
parse_expression:         # Парсинг выражения
parse_primary:            # Парсинг первичного выражения
create_node:              # Создать узел AST
```

**Грамматика (упрощенная):**
```
program     -> function*
function    -> "int" IDENT "(" ")" block
block       -> "{" statement* "}"
statement   -> var_decl | return_stmt | expr_stmt
var_decl    -> "int" IDENT ";"
return_stmt -> "return" expression ";"
expr_stmt   -> expression ";"
expression  -> primary (OPERATOR primary)*
primary     -> NUMBER | IDENT
```

### 3. Генерация кода (CodeGen)

**Файл:** `src/codegen.s`

**Задачи:**
- Обход AST
- Генерация x86_64 ассемблерного кода
- Управление регистрами
- Генерация меток для переходов

**Функции:**
```assembly
codegen_init:         # Инициализация генератора
generate_code:        # Генерация кода из AST
generate_function:    # Генерация функции
generate_statement:   # Генерация оператора
generate_expression:  # Генерация выражения
emit_code:            # Вывод кода
get_next_label:       # Получить уникальную метку
```

**Шаблоны кода:**
```assembly
# Пролог функции
pushq %rbp
movq %rsp, %rbp

# Эпилог функции
popq %rbp
ret

# Загрузка числа
movq $N, %rax

# Return оператор
jmp .L_return_main
```

## Поток данных

```
1. main.s читает исходный файл -> буфер
2. lexer.s токенизирует буфер -> поток токенов
3. parser.s строит AST из токенов -> дерево
4. codegen.s обходит AST -> ассемблерный код
5. main.s записывает код в выходной файл
```

## Управление памятью

### Статическая аллокация
- Все буферы предварительно выделены в секции `.data`
- Фиксированные размеры буферов
- Нет динамического выделения памяти

### Буферы
```assembly
input_buffer:  .space 4096   # Входной файл
token_buffer:  .space 256    # Текущий токен
ast_heap:      .space 8192   # Куча для AST
output_buffer: .space 8192   # Выходной код
```

## Соглашения о вызовах (System V ABI)

### Передача параметров
- Первые 6 параметров: %rdi, %rsi, %rdx, %rcx, %r8, %r9
- Остальные через стек

### Возвращаемое значение
- %rax для целых чисел и указателей

### Сохраняемые регистры
- Вызываемый сохраняет: %rbx, %rbp, %r12-r15
- Вызывающий сохраняет: %rax, %rcx, %rdx, %rsi, %rdi, %r8-r11

## Обработка ошибок

### Текущая реализация
- Минимальная обработка ошибок
- Возврат 0 при успехе, 1 при ошибке
- Базовые сообщения об ошибках

### Планируется
- Детальные сообщения с указанием позиции
- Восстановление после ошибок
- Несколько сообщений об ошибках за один проход

## Оптимизации

### Текущие
- Нет оптимизаций (naive code generation)

### Будущие возможности
- Constant folding
- Dead code elimination
- Регистровая аллокация
- Peephole optimization

## Расширения

### Легко добавить
- Новые ключевые слова
- Новые операторы
- Простые типы данных

### Требует значительных изменений
- Указатели и массивы
- Структуры
- Несколько единиц трансляции
- Препроцессор
